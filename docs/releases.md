# Релизы и обновления

## Как Яндекс Игры принимают обновление

- Опубликованную игру можно менять: в Консоли открыть черновик, загрузить новый архив и отправить на модерацию. **Пока идёт проверка, игроки играют в прежнюю версию** — ничего не ломается и не пропадает. ([Выпуск обновлений](https://yandex.ru/dev/games/doc/ru/console/update-game))
- Одновременно идёт только одна модерация (черновик, A/B-тест креативов или A/B-тест версий). Отказ приходит на почту с причинами, черновик становится «Отклонён».
- Перед отправкой новую версию можно проверить в [режиме черновика](https://yandex.ru/dev/games/doc/ru/console/draft-mode).
- Есть [A/B-тесты версий](https://yandex.ru/dev/games/doc/ru/console/ab-builds): часть игроков получает новую сборку — можно сравнить удержание.
- Сроки модерации в документации не названы.

## Что для этого есть в проекте

| Что | Где | Зачем |
|---|---|---|
| Список выпускаемых сцен | `src/data/release.ts` → `RELEASE_SCENES` | В релизной сборке видны только они; в разработке (`npm run dev`, `show`) — все. Готовую сцену выпускаем, следующую доделываем |
| Проверка озвучки | `scripts/zip.mjs` | Архив собирается, когда озвучены и проверены общие фразы и фразы выпускаемых сцен. Будущие сцены релиз не держат |
| Порядок озвучки | `scripts/voice.mjs` | Ежедневная озвучка сначала берёт фразы выпускаемых сцен |
| Реестр выпущенных id | `release-ids.json` | Прогресс и наклейки игроков сохранены по id уровней и героев. После сборки архива сюда дописываются выпущенные id; тест и `zip.mjs` не дают их переименовать или удалить |
| Сохранения | `normalizeSave` (`src/platform/base.ts`) | Новое поле в сохранении получает значение по умолчанию — старые сохранения читаются новой версией |
| Версия архива | `package.json` → `version` | Имя архива: `release/talking-pictures-<версия>.zip` |

## Как выпустить обновление

1. Озвучить и проверить фразы новой сцены (ежедневная озвучка + страница прослушивания).
2. Добавить id сцены в `RELEASE_SCENES`.
3. Поднять версию: `npm version minor --no-git-tag-version` (новая сцена) или `patch` (исправления).
4. `npm run release` — сборка, проверки и архив. Если что-то не так, архив не соберётся и скрипт назовёт причину.
5. Закоммитить изменения вместе с обновлённым `release-ids.json`.
6. Консоль Яндекс Игр → черновик → загрузить архив, указать версию → проверить в режиме черновика → отправить на модерацию.
7. Тексты карточки (`promo/texts.md`) поправить, если изменилось описание («теперь пять сцен»).

## План выпусков

| Версия | Что | Готовность |
|---|---|---|
| 1.0 | Лес, ферма, двор + история сцен и праздники | Осталось озвучить 148 фраз (≈ 7 дней лимита) |
| 1.1 | Кухня | ≈ 80 фраз |
| 1.2 | Вечер | ≈ 65 фраз |
| дальше | «Тук-тук, кто там?», «Где спрятался?», зима к декабрю | В плане ([разбор конкурентов](competitors-2026-10-21.md)) |

Частые обновления полезны: новая сцена — повод снова показать игру игрокам и обновить карточку.

## Чего нельзя делать в обновлении

- Переименовывать или удалять id уровней и героев выпущенных сцен — у игроков пропадут пройденные уровни и наклейки. Если герой больше не нужен, его можно сделать декорацией (`findable: false`), id оставить.
- Менять смысл поля в сохранении. Новое поле — можно (получит значение по умолчанию), старое — только читать по-старому.
